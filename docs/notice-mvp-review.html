결론

1차 MVP는 마비노기 모바일 공식 홈페이지의 공지사항 게시판만 대상으로 한다. 최신 목록을 수집하고, SQLite의 thread_id와 비교해 신규 글만 Discord Webhook으로 전송한다. 본문 수집, 요약, 기존 글 업데이트 감지는 후속 단계로 미룬다.

완료 기준

python app/main.py 1회 실행으로 수집, 신규 감지, DB 저장, Discord 전송 집계가 끝난다.

테스트 결과

Webhook 전송 성공
1차 실행 sent 10
중복 확인 sent 0
실패 0

검증 명령: .\.venv\Scripts\python.exe app\main.py. 첫 실행은 pending 10건 전송, 두 번째 실행은 중복 방지로 전송 0건.

포함 범위

  • 공지사항 게시판 목록 수집
  • 최신 N개 게시글 확보
  • thread_id 기준 신규 글 판정
  • SQLite posts 저장
  • Discord Webhook 알림
  • 수동 1회 실행 및 집계 출력

제외 범위

  • 상세 본문 수집 및 요약
  • LLM 요약
  • 기존 글의 제목/본문 변경 감지
  • 게시글 버저닝
  • 업데이트/이벤트 게시판 수집
  • APScheduler 주기 실행

동작 흐름

1

공지사항 목록 수집

공식 사이트 목록에서 thread_id, 제목, 카테고리, 작성일자, URL을 가져온다.

2

신규 글 감지

DB에 같은 thread_id가 없으면 신규, 있으면 기존 글로 본다.

3

DB 저장 후 알림

신규 글은 먼저 저장하고, Discord 전송 성공 시 notified_at을 기록한다.

4

실패 재시도 여지 유지

전송 실패 시 notified_at = NULL로 남겨 다음 실행에서 재전송할 수 있다.

데이터 모델

Column Type 의미
thread_id TEXT PRIMARY KEY 공식 사이트 게시글 ID, 1차 MVP 신규 판정 기준
board_type TEXT 1차 MVP에서는 notice
title TEXT 목록에서 수집한 제목
category TEXT 목록에서 수집한 카테고리
published_at TEXT 공식 사이트에 표시된 작성일자
url TEXT 게시글 URL
first_seen_at TEXT 봇이 처음 발견한 시각
notified_at TEXT NULL Discord 전송 성공 시각, NULL이면 전송 대기 또는 실패

Discord 메시지

[공지사항]

제목: {title}
분류: {category}
작성일: {published_at}
링크: {url}

실행 명령

python app/main.py

환경변수: DISCORD_WEBHOOK_URL

후속 단계

2차

신규 글 상세 본문 수집, 단순 본문 일부 추출 또는 요약.

3차

제목 변경, 상태 표시 변경, 본문 변경 감지와 post_versions 버저닝.

4-5차

업데이트/이벤트 게시판 확장 후 APScheduler 주기 실행.

# 📢 마비모 알림봇 개발

## 1. 프로젝트 개요

마비노기 모바일 공식 홈페이지의 주요 게시판을 주기적으로 탐색하여
신규 게시글을 감지하고, 길드 디스코드 서버에 제목과 게시글 링크 중심의 빠른 알림을 전송하는 봇을 개발한다.

---

## 2. 목표

- 공식 홈페이지의 주요 소식 자동 수집
- 신규 게시글 빠른 감지
- 길드원들이 원문을 빠르게 열어볼 수 있도록 제목과 링크 제공
- 디스코드 자동 알림 시스템 구축

---

## 3. MVP 범위

### 3.1 대상 게시판

- 공지사항
- 업데이트
- 이벤트

> ❌ 제외 (초기 MVP)
> 
> - 에린노트
> - 확인중인 현상

---

### 3.2 핵심 기능

### 1) 게시판 목록 크롤링

- 각 게시판 목록 페이지 요청
- 최신 글 N개(5~10개) 수집

---

### 2) 신규 게시글 감지

- 기준: `thread_id`
- 기존 저장 데이터와 비교하여 신규 여부 판단

---

### 3) 디스코드 알림 전송

- Discord Webhook 사용
- 제목, 분류, 작성일, 원문 링크 중심의 기본 메시지로 전송
- 본문 수집이나 요약 생성 없이 목록 데이터만 사용

예시:

```
[업데이트]

제목: 3/27 업데이트 노트
분류: 업데이트
작성일: 2026-03-27
링크: https://...
```

---

### 4) 중복 알림 방지

- `thread_id` 기준으로 중복 체크
- 발송 상태는 `notification_deliveries`의 pending/sent 상태로 관리
- 이미 `sent` 처리된 게시글 알림은 제외

---

### 5) 주기 실행

- 5~10분 간격 자동 실행
- APScheduler 사용

---

### 6) 로그 출력

- 콘솔 로그 기반

예시:

```
[INFO] 공지사항 1건 신규 발견
[INFO] 디스코드 전송 완료
```

---

### 3.3 데이터 저장

- SQLite 사용
- 저장 정보:
    - 게시판 종류
    - 제목
    - URL
    - 수집 시간
    - 알림 발송 상태와 시도 이력

## 9. 완료 기준 (MVP)

다음 조건을 만족하면 MVP 완료로 간주한다.

- 공지 / 업데이트 / 이벤트 게시글 자동 감지
- 신규 글 발생 시 5~10분 내 디스코드 알림
- 동일 게시글 중복 전송 없음
- 시스템이 자동으로 반복 실행됨
- 알림은 본문 요약 없이 제목, 분류, 작성일, 링크만 포함함

---

## 10. 핵심 전략

> ❗ "크롤링 → 신규 감지 → 디스코드 전송" 3단계에 집중한다
> 
- 작게 시작한다
- 안정화 후 확장한다
- 불필요한 기능은 뒤로 미룬다

## 11. 실행 명령

인자 없이 실행하면 기존 프로젝트 문맥과 같이 신규 글 감지를 1회 수행한다.

```powershell
python app/main.py
python app/main.py run-once
```

자동 실행은 명시적으로 scheduler 명령을 사용한다. 기본 주기는 5분이며, 시작 직후 첫 작업도 같은 interval job으로 실행한다.

```powershell
python app/main.py scheduler
python app/main.py scheduler --interval-minutes 5
```

## 12. 배포 문서

운영 배포 방식과 환경변수 정책은 [docs/deployment.md](docs/deployment.md)를 따른다.

운영 환경변수:

- `DISCORD_WEBHOOK_URL`: Discord webhook secret. 운영 로그/문서/커밋에 노출하지 않는다.
- `MABIMO_DB_PATH`: SQLite DB 경로. 운영에서는 코드 디렉터리 밖의 persistent data directory를 권장한다.
- `LOG_LEVEL`: 선택값. 미설정 시 `INFO`, 문제 분석 시 `DEBUG`.

로컬 개발에서는 `.env`를 사용할 수 있지만 Git에 커밋하지 않는다. 운영에서는 OS 환경변수 또는 서비스 전용 env 파일을 사용한다.

## 13. 확장 리스크

- 현재 DB는 `thread_id` 단일 primary key를 사용한다. 향후 업데이트, 이벤트, 확인 중인 문제 등 여러 게시판을 실제 수집할 때는 `(board_type, thread_id)` 기준 유니크 제약을 검토해야 한다.
- 미등록 `board_type` 알림은 공지사항으로 조용히 둔갑하지 않고 실패로 집계된다. 스키마 변경 전까지는 pending 상태로 남아 재시도될 수 있으므로, 실제 게시판 추가 시 라벨 매핑을 먼저 등록해야 한다.
